# Два демонстрационных аккаунта

После загрузки кода на сервер, из каталога приложения:

```sh
/opt/php/8.4/bin/php artisan demo:create
```

Команда создаёт `demo_basic` и `demo_premium`, печатает случайные пароли и табельные номера. Сохраните пароли: они хранятся только в виде хешей. Повторный запуск не меняет существующие аккаунты.

У каждого аккаунта вымышленный профиль, семь заданий на ближайшие недели и три завершённых события хронологии. У `demo_premium` доступ на 365 дней от даты запуска, у `demo_basic` — базовая версия. Календарная ссылка премиума создаётся штатно при входе.

Оба имеют должность «Рядовой пилот», доступ к личному кабинету и просмотр трёх отчётов без импорта и администрирования. Базовый аккаунт видит стандартные ограничения подписки.

Для добавления по 10 вымышленных записей AirFASE, RRJ-Express и Зелёной зоны существующему `demo_premium`:

```sh
/opt/php/8.4/bin/php artisan migrate --force
/opt/php/8.4/bin/php artisan demo:reports
```

Эти записи видны только `demo_premium` и администраторам. Руководители и остальные пилоты их не видят; пометка `demo_user_id` проверяется на сервере. Демозначения доступны в фильтрах владельца и администраторов, но не попадают в общие кэши и справочник отрядов. Повторный запуск не добавляет дубли, не меняет пароли, подписку или существующие строки. Запускайте после применения миграции, до возобновления работы приложения. Реальные строки имеют пустое `demo_user_id` и сохраняют прежнюю видимость.

Учётные данные портала, Telegram, задачи парсера и подписки push не создаются. Демо-премиум помечен источником `demo`, суммой 0 и комментарием: это не реальная оплата. Для обязательного поля автора используется сам демоаккаунт, а не настоящий администратор.
