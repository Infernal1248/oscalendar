# ЮKassa

Поддерживается только боевой магазин. Настройки сервера:

```dotenv
YOOKASSA_ENABLED=true
YOOKASSA_SHOP_ID=идентификатор_боевого_магазина
YOOKASSA_SECRET_KEY=секретный_ключ_боевого_магазина
YOOKASSA_FRONTEND_URL=https://oscalendar.ru
```

После обновления кода: `php artisan config:clear`. Миграции не нужны.
Старые `YOOKASSA_MODE` и `YOOKASSA_TEST_*` больше не используются и могут быть удалены из `.env`.
Адрес webhook остаётся прежним: `https://oscalendar.ru/api/payments/yookassa/live`.
События: `payment.succeeded`, `payment.canceled`, `payment.waiting_for_capture`.

Сумма фиксируется при создании заказа. Возврат из магазина не подтверждает оплату:
сервер проверяет её через API, сверяет магазин, сумму, валюту и исключает тестовый платёж.
Повторный webhook не выдаёт доступ повторно. Ключ идемпотентности и тело запроса сохраняются;
неопределённое создание не повторяется после 23 часов (срок ключа у ЮKassa — 24 часа).

После фиксации оплаты уведомления отправляются сразу, без cron. Ошибка доставки не отменяет подписку.
Успешные отправки не повторяются; при потере подтверждения внешнего сервиса редкий дубль сообщения возможен.
Для ручной сверки: `php artisan payments:reconcile`.
Для повторной отправки: `php artisan payments:notify --order=UUID` (не чаще раза в 5 минут, до 10 попыток).
Фоновых повторов нет. Чек в «Мой налог» оформляется вручную.
Автосписаний и автоматической обработки возвратов нет.

## История тестовых платежей

Существующие записи, даты, суммы и выданный ими доступ не удаляются и не пересчитываются.
Незавершённые тестовые заказы больше не обслуживаются и не мешают новой боевой покупке.
Тестовый webhook удалён; ручные команды сверки и уведомлений пропускают тестовые заказы.
Пометка тестового источника в истории сохранена, чтобы не путать записи с реальными поступлениями.

## Смена уровня администратором

Пользователи → действие добавления оплаты → «Изменить уровень подписки».
Изменяются все неотменённые действующие и будущие периоды, предоставляющие доступ.
Суммы, даты, длительность, исходные заказы и идентификаторы оплат сохраняются.
В комментариях записей остаются дата, администратор и прежний/новый уровень.
Деньги не списываются, новая оплата не создаётся. Незавершённая боевая оплата блокирует смену уровня.
Продление через форму добавления оплаты по-прежнему выполняется в текущем уровне.

Автотесты используют имитацию API без реальных списаний.
