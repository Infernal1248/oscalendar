# Уровни подписки и управление ценами

- Без подписки: прежние бесплатные возможности, демонстрационные заглушки таблиц.
- `basic`: календарь, полная хронология и остальные возможности личного кабинета, без просмотра отчётов.
- `extended`: базовые возможности и чтение всех трёх отчётов. Должность по-прежнему ограничивает строки.
- Администратор имеет полный доступ без оплаты. Импорт и управление пользователями остаются отдельными правами.

На странице администратора «Подписки» доступны вкладки «Цены» и «История оплат». Цены в БД хранятся в копейках, редактируются в рублях в отдельном модальном окне; изменение не пересчитывает старые оплаты. Модалка покупки показывает сравнение возможностей и получает цены с сервера при открытии. История объединяет всех пользователей, поддерживает серверные фильтры в заголовках, сортировку, постраничный просмотр и отмену ошибочной записи (не банковский возврат).

Внесение оплаты осталось в меню пользователя. Нужно выбрать уровень; нулевая сумма по-прежнему допустима. Смена уровня при наличии неистекшего оплаченного периода запрещена до отдельной реализации перехода. После окончания периода можно выбрать любой уровень. Онлайн-оплата пока ведёт на прежнюю заглушку.

В профиле кнопка продления появляется, когда до конца подписки осталось менее трёх календарных месяцев (по датам UTC, как сами оплаченные периоды). Для базовой подписки доступна кнопка «Улучшить подписку» с предварительным расчётом: текущая цена расширенной минус текущая цена базовой за полный исходный срок каждого неотменённого, ещё не закончившегося базового периода, включая будущие. Истёкшие периоды не учитываются; отрицательная доплата заменяется нулём. Реально внесённая сумма, включая бесплатную выдачу администратором, не влияет на расчёт. Даты окончания не сдвигаются.

Это пока только расчёт: переход к оплате открывает заглушку, права и записи оплат не меняются. Фактическое повышение после подтверждённой оплаты и его отмену необходимо подключить вместе с платёжным процессом; предварительная сумма не является зафиксированным платёжным заказом.

## Обновление сервера

Сначала сделайте резервную копию БД. На время загрузки нового бэка, фронтенда и миграции остановите доступ к приложению:

```sh
/opt/php/8.4/bin/php artisan down
# Загрузить новый код бэка и сборку фронтенда.
/opt/php/8.4/bin/php artisan migrate --force
/opt/php/8.4/bin/php artisan optimize:clear
/opt/php/8.4/bin/php artisan up
```

Миграция классифицирует существующие оплаты по старым правам чтения таблиц **до** удаления этих прав из ролей. Без прав чтения — базовая, с правами чтения хотя бы одной таблицы — расширенная. Это сохраняет базовый уровень Макса и Алексея при текущих ролях. Даты, суммы и статус отмены сохраняются; новые оплаты не создаются. `demo_basic` остаётся без подписки, `demo_premium` сохраняет прежний полный доступ как расширенный.

Ручная выдача прав чтения отчётов запрещена API и скрыта в редакторе ролей. Даже старые или вручную записанные в БД права чтения не обходят проверку подписки. Пустые стандартные роли просмотра удаляются, остальные права сохраняются. Перенос оплат и очистка ролей выполняются в одной транзакции. Обратная миграция намеренно запрещена: для отката необходима согласованная резервная копия БД и прежний код.
